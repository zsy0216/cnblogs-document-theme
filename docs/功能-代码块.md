# 代码块：行号、语言标签、复制

> 这块的坑不在「怎么写行号」，而在**行号有两套来源**。搞不清归属就会出现「后台明明开了行号，页面上一根都没有」。

---

## 一、博客园自己的代码块长什么样

Markdown 文章里写 ` ```java ` 时，服务端输出的是最朴素的：

```html
<pre><code class="language-java">transient Object[] elementData;</code></pre>
```

**整段代码就是一个文本节点**，没有逐行 DOM。浏览器里再被博客园的前端脚本加工成：

```html
<pre class="line-numbers highlighter-prismjs prismjs-lines-highlighted code-theme-dark language-java">
  <code class="highlighter-prismjs language-java">
    <span class="token keyword">transient</span> <span class="token class-name">Object</span>[]
  </code>
  <span aria-hidden="true" class="line-numbers-rows"><span></span><span></span>…</span>
</pre>
```

两个关键事实：

| 事实 | 意味着什么 |
|:---|:---|
| 页面引了 `prism.js` 与 `prism-line-numbers.min.js` | 语法高亮和行号由**园方**提供，主题不需要再造一套 |
| 行号容器 `.line-numbers-rows` 是 `position:absolute; left:-3.8em; width:3em` | 它完全靠 `pre` 的 `padding-left` 留位置，**padding 一变小就会被裁掉** |

## 二、为什么原来一根行号都看不到

主题原来把 `pre` 的左右内边距统一压成 18px（为了三栏里的紧凑排版）：

```css
#cnblogs_post_body pre { padding: 16px 18px !important; }
```

而园方行号需要的留白是 **3.8em ≈ 49px**，位置还从内容区往左再退 3.8em。18px 只够露出最右一两个字，剩下的部分被外层容器的 `overflow:hidden` 裁掉 —— 表现就是**行号完全不显示**，而不是显示得难看。

| 现象 | 根因 | 修法 |
|:---|:---|:---|
| 行号一根都不出现 | `pre` 左内边距 18px < 园方需要的 3.8em，行号容器落在容器外被裁 | `pre.line-numbers { padding-left: 3.8em !important }` |
| 行号出现了但行数不对 | 主题抢先按 `\n` 拆行，Prism 随后重写 `code` 内容，行号容器按被改过的 DOM 算行数 | **不要和 Prism 抢**，见下一节 |
| 行号颜色与暗色不搭 | 园方默认 `#999` | `.line-numbers-rows > span::before { color: var(--pre-num) }` |

## 三、现在怎么分工

行号归属按「有没有园方行号」分两条路，**互不重叠**：

| 场景 | 谁画行号 | 做法 |
|:---|:---|:---|
| 页面有 `prism-line-numbers`（博客园默认） | 园方 Prism | 主题只包一层工具条，`padding-left` 让到 3.8em，行号配色接管到 `--pre-num` |
| 没有 Prism 行号 | 主题 | `load` 之后按 `\n` 拆成 `.qb-cl`，用 CSS 计数器画行号（左侧 `position:sticky`，横向滚动时行号不动） |

**为什么判断放在 `load` 之后**：`prism-line-numbers` 是客户端加载的，主题脚本跑在解析期（比首帧还早），那时脚本标签还没解析到、`<pre class="line-numbers">` 也还没加上。当场判断必然得出「没有园方行号」的错误结论，于是抢先拆行，随后被 Prism 整个重写覆盖 —— 行号容器还会因为 DOM 里没有换行文本而只算成 1 行。

所以 `enhanceCode()` 只做**不冲突的部分**（包工具条、算语言），行号留到 `load` + 350ms 后再定：

```js
if (it.pre.querySelector('.line-numbers-rows')) continue;  // 园方已接管
if (it.code.children.length) continue;                     // 已高亮但没开行号，拆了会丢色
if (wrap.classList.contains('no-line-numbers')) continue;  // 用户关掉了
```

三条里任一条成立都不自建行号 —— 宁可不画，也不把已经上色的代码拍平成纯文本。

## 四、工具条

每个代码块上方一条 30px 的工具条，左边语言标签（取 `class="language-xxx"`，大写显示），右边「复制」。

- 复制走 `navigator.clipboard.writeText()`，非安全上下文回落到 `execCommand`；文案 1.4 秒后复原。
- 复制的是**拆行前的原文**，不是 `code.textContent`。自行拆行后 span 之间没有 `\n` 文本节点，直接读会把整段粘成一行。
- 行号是伪元素生成的，**选中复制不会带上行号**；手动框选时浏览器按块级元素自动补换行。

## 五、配置

```js
window.LS_CONFIG = {
  // 默认全开，需要时再放开
  code: { lineNumbers: false, copy: false }
};
```

| 写法 | 效果 |
|:---|:---|
| 不写 | 行号 + 语言标签 + 复制，全开 |
| `code: { lineNumbers: false }` | 去掉行号（园方那套也一起收掉），保留工具条 |
| `code: { copy: false }` | 去掉复制按钮 |
| `code: false` | 整块不加工，回到博客园原始代码块 |

## 六、排错

| 现象 | 先查什么 |
|:---|:---|
| 完全没有工具条 | 文章是否在 `#cnblogs_post_body` 里；`code:false` 是否开着 |
| 有工具条、没有行号 | 后台「显示行号」是否开着；`pre` 的 `class` 里有没有 `line-numbers` |
| 行号与代码重叠 | `pre` 的 `padding-left` 是否被别的 CSS 改小（要 ≥ 3.8em） |
| 复制出来是一行 | 是否被别的脚本改过 `code` 的 DOM；复制逻辑读的是 `raw` 快照，正常不会出现 |
| 富文本「插入代码」的块没工具条 | 预期行为：`.cnblogs_code` 是园方的表格结构，自带行号，主题不加工 |
