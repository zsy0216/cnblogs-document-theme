# 分类与标签

v7.25 加的两处：**文章页标题下的分类 + 标签胶囊**、**列表页顶部的分类筛选条**。
不需要配置，不需要往后台多贴字段，全部由页脚脚本按页面数据生成。

| 位置 | 内容 | 数据来源 | 请求成本 |
|:---|:---|:---|:---|
| 文章页标题下 | 1 个分类胶囊 + 最多 4 个标签（余下折成 `+n`） | `<meta name="keywords">` + 全站分类名单 | 名单一次，缓存 7 天 |
| 列表页顶部 | `全部` + 7 个分类（带篇数），当前项高亮 | 全站分类名单 | 同上，同一份缓存 |

---

## 一、为什么不用「原生那块」

博客园标准皮肤会在 `#blog_post_info` 里输出「分类：… 标签：…」，但这套模板**一个都没有**。2026-11-17 用 curl 抓线上页面核对：

| 选择器 | 列表页 | 文章页 |
|:---|:---|:---|
| `#EntryTag` | — | **不存在** |
| `#BlogPostCategory` | — | **不存在** |
| `#blog_post_info` | — | 存在，但**是空 div** |
| 每篇文章的分类 / 标签 | **没有** | 只能从 `meta[name=keywords]` 间接读 |

结论有两条：

1. 主题里那段 `#EntryTag` 样式（圆角标签）从来没有生效过，属于死代码。留着是为了换到会输出它的模板时兜底，现行展示走 `.qb-tax`。
2. 列表页的每篇文章分类**拿不到**。唯一的反查办法是抓 7 个分类页（约 140KB）遍历每篇属于哪个分类，代价不成比例。所以列表页不做「每篇贴分类」，改做顶部筛选条。

## 二、文章页：标题下的胶囊

位置在 `h1.postTitle` 之后、正文之前。放在这里而不是文末落款，是因为详情页的 `.postDesc` 是「posted @ 日期 作者 阅读」那条**页脚**，不是标题下的元信息。

```
计算机网络 · TCP/IP  DHCP  ARP  NAT  +1
└── 分类：实心浅底 + 圆点 + 600 字重
             └── 标签：浅灰底、常规字重，超 4 个折成 +n，点开全展开
```

分类和标签**必须视觉可分**：一篇文只有一个分类、可以有多个标签，同一种样式读者会当成同类东西。

### 数据从哪来

文章页的 `meta[name="keywords"]` 内容恰好是「本文标签 + 分类名」，分类排在最后。抽样 4 篇与 `/rss` 的 `<category term>` 逐条比对，全部吻合：

| 文章 | keywords |
|:---|:---|
| 23690291 | `TCP/IP,DHCP,ARP,NAT,子网掩码,计算机网络` |
| 23598351 | `新概念英语,英语语法,数词,词法,英语` |
| 23594509 | `英语`（无标签，只有分类） |
| 12038083 | `编程语言`（无标签，只有分类） |

但「末位是分类」只当**临时判据**，不当事实：

- 分类名单到手后，从后往前按名字核对，核对上的才是分类，其余全部当标签；
- 一个都核对不上（比如后台改过「关键字」设置），就不显示分类胶囊，宁可少一个，不挂错的；
- 名单没到手时先用末位占位，名单回来再复核一次。

## 三、列表页：顶部分类筛选条

挂在 `.forFlow` 最前面，在文章列表之上。当前站点的分类很少（7 个），一行放得下，所以不折叠、不做下拉。

- **首页**：`全部` 高亮。
- **分类页**（`/category/<id>.html`）：保留同一条，并高亮当前分类，点进去不会「条没了」。当前项靠 URL 里的分类 id 匹配，不依赖页面里的标题文本。
- **标签页 / 归档页**：不挂。它们用的是 `.PostList` / `.entrylistItem` 结构，硬挂会挤在错误的位置。
- **窄屏**：不换行，改成横滑；还能往右滑时给右边缘渐隐（`.qb-fade-r`），避免最后一个胶囊被硬切一半、看起来像布局溢出。滑到末尾自动摘掉渐隐。

## 四、缓存与首帧

分类名单来自 `/categories` 页面（同源、服务端渲染，约 20KB），解析 `.category-list-item a` 的「名字(篇数)」。

- 存 `localStorage`，键为 `qb-cats-v1:<host>/<博客名>`，有效期 **7 天**；
- 命中缓存时两个页面都是**同步画完**，不发请求，切换页面零等待；
- 未命中时先按占位方案渲染，请求回来后复核。`TAXO.pending` 会被首帧闸门读到：**最多等 30 帧（约 500ms）**，宁可首访晚一点，也不让筛选条在页面显示之后再「长出来」；
- 请求失败（404 / 离线）就降级：文章页只剩标签，列表页不建空条。不做任何硬编码兜底。

## 五、已知边界

- **同名标签**：如果某篇的标签与某个分类完全同名（例如标签也叫「英语」），它会被当成分类吃掉一个。当前 7 个分类名与现有标签没有重名（标签是「英语语法」「新概念英语」这类），属于可接受风险。
- **后台改了「关键字」设置**：`meta[name=keywords]` 的内容会变，分类判定随之失效，表现为文章页不显示分类胶囊。这是有意的降级，不会出现错分类。
- **不加配置项**：和主题其它自动项一致，没有 `taxonomy:false` 这类开关；不需要就只能删掉页脚里 `initTaxonomy` 那段调用。
- **没有用 RSS**：`/rss` 是 Atom，20 条里带 `<category term>`，但只覆盖最近 20 篇、且不含分类。用作列表页数据源会出现「前 20 篇有、翻页就没了」的不一致，所以只作核对用，不作数据源。

## 六、验证

```bash
node _dev-tools/verify-taxonomy.js
```

覆盖：胶囊只插一次、插在标题之后正文之外、分类/标签样式区分、`+n` 折叠与展开、链接编码、列表页条位置与篇数、首页与分类页的高亮、窄屏横滑与渐隐、缓存命中不再请求、`/categories` 失败时的降级。
