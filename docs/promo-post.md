# 给博客园换一身「文档站」皮肤：一个三栏 + 暗黑模式的开源主题

> 仓库：<https://github.com/zsy0216/cnblogs-document-theme>
> 技术栈：纯 CSS（Grid）+ 原生 JS，零依赖、零构建、零后端
> 当前版本：v7.28，MIT

## 一、为什么想换皮

博客园自带的皮肤，基本都是「博客时间线」审美：正文居中、侧栏堆在右边、区块之间靠缩进和分割线区分。

写技术笔记的时候，这套版式有三个明显的不顺手：

1. **长文没有目录**。文章一长，只能靠滚动条硬扛，回头找某一节要翻半天。
2. **侧栏和正文挤在一起**。公告、搜索、常用链接全堆在同一列，视觉噪音比信息还多。
3. **没有暗色**。晚上看白底文章，眼睛是真的累；自己写 CSS 又容易和园方样式打架。

于是我按「文档站」（类似 VitePress / Docusaurus）的版式思路，把博客园重写了一遍。所有选择器都对着 2026 年 11 月博客园真实 DOM 校准过，不再假设不存在的节点。

## 二、长什么样

**首页**：左中右三栏，左边是全文文章列表，中间是文章卡片，右边是公告和常用链接。列表顶上多了一行分类筛选（`全部` + 每个分类及其篇数），点一下就进对应分类页。

![首页效果](https://gcore.jsdelivr.net/gh/zsy0216/cnblogs-document-theme@v7.28/docs/images/home-v7.png)

**文章页**：左边是正文 H1–H4 自动生成的目录，右边是卡片式侧栏，正文独占中栏；标题下面一行是这篇文章的分类和标签。

![文章页效果](https://gcore.jsdelivr.net/gh/zsy0216/cnblogs-document-theme@v7.28/docs/images/post-v7.png)

**暗色模式**：配色对齐 GitHub Dark —— 底色 `#0d1117`、卡片 `#161b22`、描边 `#30363d`、正文 `#c9d1d9`。不是简单把白底刷黑，而是每个层级都重新定了一套色。右上角 🌙 一键切换，状态存本地，首次访问跟随系统偏好。

![暗色首页](https://gcore.jsdelivr.net/gh/zsy0216/cnblogs-document-theme@v7.28/docs/images/home-v7-dark.png)

**手机**：断点以下收成单栏，顶栏换成汉堡按钮 + 右侧抽屉，抽屉里的条目和桌面菜单同源，不会两套配置各说各话。

![手机导航](https://gcore.jsdelivr.net/gh/zsy0216/cnblogs-document-theme@v7.28/docs/images/mobile-menu-v7.png)

## 三、都做了哪些事

### 1. 三栏布局：纯 CSS，不动一行 HTML

博客园的 DOM 结构是 `#main` 里塞 `#mainContent` 和 `#sideBar`。想做成三栏，常规做法是 JS 搬节点，但那样每次刷新都会闪一下。

这里用的是 Grid，而且**一个节点都不搬**：

```css
#main {
  display: grid;
  grid-template-columns: 260px minmax(0, 1fr) 292px;
  gap: 22px;
}
#sideBar { display: contents; }   /* 只摊平外面那层壳 */
#sideBarMain { grid-column: 3; }  /* 博客园自带的侧栏容器，原地当右栏 */
#qb-left      { grid-column: 1; } /* 左栏由脚本新建：文章列表 / 目录 */
#mainContent  { grid-column: 2; } /* 中：正文 */
```

关键在于**不做 DOM 搬运**。早期版本用 JS 把侧栏卡片搬进自建容器，结果每次刷新都要闪一下；现在右栏直接用博客园自己的 `#sideBarMain`，卡片本来就在里面，一个节点都不动。右栏内容晚到只会改变它自己的高度，推不动正文和左栏——这是「切页不抖」的结构性原因。

断点也很好写：≤1024px 收成两栏（隐藏右栏），≤860px 单栏。

### 2. 左栏目录：按页面类型自动切换

同一个左栏，在不同页面显示不同内容：

| 页面 | 左栏内容 |
|:---|:---|
| 首页 | 全部文章标题 + 日期 |
| 文章详情 | 正文 H1–H4 目录（点击跳转） |
| 分类 / 标签 / 归档 | 分类名 / 标签名 / 月份 |

逻辑很简单：进入页面 → 左栏拿到什么就渲染什么，正文里有标题就写目录，没有标题就写文章列表。没有额外请求，也没有额外配置。

### 3. 暗黑模式：一套变量，全局换肤

整个主题的配色都走 CSS 变量，暗色只需要覆盖变量值：

```css
body.qb-dark {
  --bg:     #0d1117;
  --card:   #161b22;
  --line:   #30363d;
  --ink:    #e6edf3;
  --body:   #c9d1d9;
  --meta:   #8b949e;
  --accent: #58a6ff;
}
```

右上角的 🌙 按钮切换，状态存在 `localStorage`，刷新不丢；首次访问会跟随系统的 `prefers-color-scheme`。

值得一提的是，博客园有些原生区块（公告、评论框、代码块）自带内联浅色，光靠变量覆盖不掉。这部分单独写了层暗色补丁，把它们压成半透明深底，保证整页没有「白块残留」。

### 4. 顺手修的几个老问题

- **回到页首**：滚动超过 300px 出现，点击平滑回顶
- **列表页统一卡片化**：分类页、标签页、归档页不再是裸列表，跟首页一个观感
- **右侧「搜索」标题被压成竖排**：`flex` 布局下 `white-space` 没锁住，两行挤成一列字，加 `flex-shrink: 0` 解决
- **favicon 接管**：见下一节

### 5. favicon：一个被很多人踩过的坑

博客园的「页首 HTML 代码」并不是插到 `<head>` 里，而是塞在 **body 里的 `#page_begin_html`** 容器中。而浏览器只认 `<head>` 里的 `<link rel="icon">` —— 所以你往页首贴 favicon，**基本不会生效**。

更麻烦的是两件事：

1. 博客园 `<head>` 里本来就写死了 `favicon_v3_3.ico` 和 `.svg` 两个默认图标，你追加一个，就变成三个图标并存，浏览器爱用哪个用哪个；
2. 园方脚本在页面加载完几秒后，还会再往 `<head>` 里补一次默认图标。

所以主题脚本干了三件事：把用户图标搬进 `<head>`、清掉所有非用户图标、用 `MutationObserver` 持续拦截后续插入。搬完 check 一遍，`<head>` 里只剩你设置的那一个。

### 6. 切页不抖：三处 1~2 像素的账

版式对了不代表观感对了。逐帧录屏（CDP screencast，按每帧 jpeg 字节数判空白）才发现，切页时还有三处不该有的跳变：

| 现象 | 根因 | 修法 |
|:---|:---|:---|
| 顶栏从离顶部 8px 处弹回 0 | 浏览器给 `<body>` 的**默认边距**，在样式到位前一直存在 | 首帧样式里 `html,body{margin:0}` |
| 顶栏塌成一条线再张开 | 页首里的顶栏是外层 div，撑高度的内层还没解析到时高 0 | `.qb-nav{min-height:58px}` |
| 整页先按园方皮肤画一遍再换肤 | CSS 在 js 里，脚本没到就没有样式 | 完整样式放回「页面定制 CSS」字段，js 检测到标记就跳过注入 |

再加上跨文档视图过渡（`@view-transition`）给顶栏单独命名、两张快照强制不透明，切页过程空白帧从 **3 帧降到 0 帧**，`nav.height` 全程恒为 59px。

不支持跨文档视图过渡的浏览器（如 Firefox）会忽略这几条规则，退回普通导航，不会更差。

### 7. 分类与标签：先查清数据在哪，再决定做什么

博客园这套模板下，**每篇文章的分类和标签在 HTML 里是不存在的**：列表页 `.day` 只有标题、摘要、日期；详情页 `#EntryTag`、`#BlogPostCategory` 两个节点都没有，`#blog_post_info` 是个空 div（网上很多美化代码里那段标签样式，其实一直是死代码，包括我自己的旧版）。

实测能拿到的是这两处：

| 数据 | 从哪来 | 覆盖范围 |
|:---|:---|:---|
| 本文标签 + 分类名 | 详情页 `<meta name="keywords">`，内容是「标签…,分类名」，分类在末位 | 每篇文章都有，**零请求** |
| 全站分类清单 | 博客的 `/categories` 页（分类名 + 各自篇数） | 全站一次，缓存 7 天 |

所以详情页的胶囊这么做：标签直接读 `keywords`；分类拿那份清单从后往前核对，对不上就不显示 —— 宁可少显示，也不挂错。标签超过 4 个折成 `+n`，点一下展开。

列表页则不为每篇打标：那需要抓 7 个分类页反向建映射（约 140 KB），翻页还会越翻越不一致。改成在列表顶上放一条分类筛选，首页高亮「全部」、分类页高亮当前项；窄屏不换行改横滑，末端被裁时加一层右缘渐隐。

拿不到数据时的降级是设计的一部分：文章页只留标签、列表页不建空条，不出现空壳组件。

### 8. 手机端：从「横滑菜单」到汉堡抽屉

第一版窄屏是把桌面菜单改成横向滚动，实测走不通：390px 下 9 个条目只露出 4 个，剩下 5 个没有任何视觉线索。现在是汉堡按钮 + 右侧抽屉，条目从桌面菜单克隆，共用同一份 `nav` 配置；打开时锁滚动，点遮罩或按 Esc 关闭。

顺带修掉一个更隐蔽的问题：右栏在窄屏**没有真正隐藏** —— 容器上写了 `display:none`，但更早的一条 `display:block !important` 把它盖掉了，实际效果是 370×1408px 的一块侧栏堆在正文下面。整页高度从 8754px 降到 7336px。

另外，抽屉是脚本建的，所以 CSS 只在 `<html>` 挂上 `qb-mnav` 之后才隐藏横滑菜单 —— 脚本没跑成功时至少还留着原来的横滑入口，不会变成「没有导航」。

### 9. 页脚：一行写死的署名

页脚最后一行是 `Theme powered by cnblogs-document-theme ↗`，链回仓库：12px、比备案那行再淡一档、悬停提亮、打印时隐藏。同时写一条 `<meta name="generator">`，零视觉成本，也是 WordPress / Hugo 的通行做法。

这行**写死在 js 里**，配置对象里没有对应的键，写 `credit: false` 不生效，界面上也没有开关。边界说清楚：任何前端代码都锁不住，fork 之后删掉一行就没了，MIT 允许 —— 所谓写死只是不给开关，不是防破解。我把它当成「让下一个人找到这个主题」的成本，公开写在这儿，不藏着。

## 四、怎么装（两个字段，五分钟）

> ⚠️ 第 0 步最重要：**设置 → 皮肤 → 选 `Custom`（自定义）**，否则后面全都不生效。

样式和逻辑都在仓库里，你只需要往后台贴两个字段 —— **不用上传文件，不用 fork，不用打 tag，也不用改任何地址**：

> 动手前先把**页脚 HTML 代码**和**公告**两个字段清空。页脚里若残留旧版内联脚本，
> 它会自己建一套右栏，和新版同时跑，怎么贴都不对。

| 步骤 | 贴到哪 | 贴什么 | 大小 |
|:---:|:---|:---|---:|
| 1 | 页面定制 CSS 代码 | `dist/paste/样式.css` | 53 KB |
| 2 | 页首 HTML 代码 | `dist/paste/页首.html` | 4.3 KB |
| 3 | 页脚 HTML 代码 / 公告 | 全选删除（公告不删也行，会自动取后台原文） | — |

保存后前台 `Ctrl+F5` 强刷。

页首里那段加载器会从 `gcore.jsdelivr.net`（GitHub 仓库镜像）取 js，取不到自动换 `cdn.jsdelivr.net`，两个都钉了版本号 —— 你看到的就是装的这一版，不会哪天样式突然变了。那份 js 由我维护在仓库里，发版时我打 tag，你这边不用做任何事。

**页首里没有任何我的信息**：顶栏品牌取你页面标题里的博客名，菜单指向你自己的站，公告用你后台那份原文，连 favicon 都不碰。

升级时把页首里那行地址的版本号改掉、并重贴一次 CSS（约 53 KB）即可；只想改配色、菜单、公告，改页首里那段 `LS_CONFIG` 就行，不用重新贴 CSS。

顶栏菜单、公告文案、强调色都不必改源码，页首那段 `window.LS_CONFIG` 里配就行：

```js
window.LS_CONFIG = {
  accent: '#d05ce8',
  nav: {
    brand: '你的博客名',
    links: [
      { t: '首页', h: 'https://www.cnblogs.com/你的博客名/' },
      { t: '归档', h: 'https://www.cnblogs.com/你的博客名/p/archive/2026/11' },
      { t: 'GitHub', h: 'https://github.com/你的账号', b: 1 }   // b:1 = 新窗口
    ]
  },
  notice: { show: true, title: '公告', html: '<p>写点什么</p>' }
};
```

**回滚**：清空「页面定制 CSS」「页首 HTML」「页脚 HTML」三个字段，就恢复默认外观。旧版 v6.28 已封存在 tag `v6.28`，需要时从仓库取出重贴。

## 五、几个设计取舍

**为什么不用框架？** 博客园的自定义代码是直接贴进页面的，没有构建流程。引入 Vue/React 意味着要么上 CDN（多一个外部依赖、多一次阻塞），要么把运行时整个贴进去（几十 KB）。这个主题的交互都是小东西 —— 切暗色、回顶、生成目录、分类筛选、手机抽屉 —— 原生 JS 压缩后约 65 KB，比一份框架运行时还小，而且没有构建步骤、没有额外的 CDN 依赖。

**为什么 CSS 要分全版和压缩版？** `theme-v7.css` 是带完整注释的开发版，`theme-v7.min.css` 是发布版，压掉 44%（95 KB → 53 KB）。博客园的 CSS 字段实测能吃下五万字符（现在这份就是 53 KB），但注释留在生产环境没有收益，压一下更稳。

**为什么强调「对着真实 DOM 写」？** 网上很多博客园美化代码是几年前的，选择器早就失效了，贴上去一半样式不生效，还容易和园方新样式打架。这个主题的每条选择器我都在线上页面验证过。
