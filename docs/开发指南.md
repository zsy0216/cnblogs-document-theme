> 这份讲「怎么改这个主题」：源码在哪、改了怎么构建、版本号怎么维护、压缩会不会压坏。
> 只想装上用，看 [README](../README.md)；安装出问题看 [安装-详解](安装-详解.md)。

## 二、一条命令完成构建

```bash
python _dev-tools/bump-version.py -n "本次改动一句话"
```

它会按顺序做四件事：

1. 版本号 +1（`v7.17` → `v7.18`）
2. 改四份文件的头注释版本号 + 重写 min 版横幅
3. 重建三个产物（min CSS → min 页脚 → 合并 js）
4. 往 `CHANGELOG.md` 插一行

只体检、不动文件：

```bash
python _dev-tools/bump-version.py --check
```

重新生成粘贴包（改了页首模板，或想换 `LS_CONFIG` 默认值时才需要）：

```bash
python _dev-tools/gen-deploy.py                 # 托管版两份 -> dist/paste/
python _dev-tools/gen-deploy.py --mode inline   # 内联版四份 -> dist/paste/inline/
python _dev-tools/gen-deploy.py --mode hybrid   # 混合版四份 -> dist/paste/hybrid/
python _dev-tools/gen-deploy.py --check         # 只比对现有产物是否与源码一致
```

### 版本号约定

| 文件 | 版本号位置 |
|:---|:---|
| `css/theme-v7.css` | 头部第 2 行（**真源**） |
| `snippets/footer-script-v7.html` | 外部注释第 1 行 + 脚本内第 1 行 |
| `css/theme-v7.min.css` | 第 1 行（压缩时唯一保留的横幅） |
| `snippets/footer-script-v7.min.html` | 第 1 行（同上，生成物） |
| `dist/document-theme.js` | 第 1 行（合并版横幅，生成物） |

- **不要手改其余文件的版本号**，手改会被 `--check` 判为不一致
- 每交付一次改动 +1，对应 git 一次提交、CHANGELOG 一行
- min 版头部刻意保留一行版本注释 —— 压缩会删掉其它所有注释，这行是**线上唯一能自查版本的证据**：粘贴后在页面 `Ctrl+U` 搜「流苏主题 v7.」就知道线上跑的是哪一版，不用猜缓存

完整历史见 [CHANGELOG.md](../CHANGELOG.md)。

## 三、压缩做了什么

只做无损变换，不改变任何行为：

| 产物 | 处理 |
|:---|:---|
| CSS | 删注释、折叠空白、块尾分号、`0px`→`0`、`0.5`→`.5`、`#ffffff`→`#fff` |
| 页脚 JS | 删注释、删每行缩进、删空行、折叠行内空格 |

**不动的**：变量名、表达式、语句顺序、换行位置。保留换行是为了 ASI 语义不变，出问题时还能按行定位。

页脚压缩器最容易翻车的地方是把字符串或正则里的空格也折叠掉（`'a  b'`、`/\s+/`）。所以先把字符串与正则字面量整体抽成占位符，压缩完再还原 —— 这一步保证 400 多个字面量原样保留。

### 怎么确认压缩没压坏

```bash
node _dev-tools/verify-min-parity.js
```

对 6 个页面（首页 / 随笔分页 / 文章页 / 归档页 / 标签页 / 分类页）分别注入**源版**和**压缩版**，逐项比较：

- 结构：左栏面板标题、目录条目、分页按钮文本、卡片高度、归档年月与文章数、回到顶部按钮属性
- 样式：15 个代表元素 × 15 项计算样式（背景色、字色、字号、字重、内外边距、边框、圆角、阴影、行高、宽高）
- 报错：过滤掉博客园自身的 `Permissions policy` 噪音后应为 0

> 验证脚本会先清掉页面上旧脚本留下的 `.qb-archive` 等结构，否则幂等守卫会让新脚本直接 `return`，等于没测到。

## 四、验证脚本

| 脚本 | 验什么 |
|:---|:---|
| `verify-min-parity.js` | 源版 vs 压缩版，6 个页面逐项对拍 |
| `verify-bundle.js` | 内联 vs 合并 vs 合并+配置，三方案对拍 |
| `verify-config.js` | 外链加载、暗色三层优先级、非法配置不崩 |
| `probe-navflash.js` | 切页过程逐帧录屏，判空白帧（CDP screencast） |
| `probe-navmove.js` | 跨文档累积采样 `nav.top` / `nav.h` / 列宽，判位置抖动 |
| `probe-hosted.js` | 托管版首帧：本地 http 托管 js，可注入延迟模拟弱网 |
| `shot-docs.js` | 截 README 用的效果图（`node _dev-tools/shot-docs.js --dark` 多出一张暗色） |

探针依赖 playwright，`node_modules/` 已在 `.gitignore` 里，换机器要先 `npm i playwright`。

## 六、改代码时的两个硬约束

- **强调色不能只写 `:root`**：暗色模式下 `html.qb-dark` 与 `body.qb-dark` 各自重定义了 `--accent`，只写一处会被覆盖回去。脚本注入的是 `:root,html.qb-dark,body.qb-dark` 三选择器并列。
- **页脚字段里不能出现 `</script>` 字面量**：哪怕是注释里的示例。HTML 解析器只看这个序列，会当场闭合标签，后面的代码全变成文本。文档与注释里一律写「script 标签」而非原文。

## 七、工作流

```
改 theme-v7.css / footer-script-v7.html
  ↓
python _dev-tools/bump-version.py -n "改动摘要"
  ↓
node _dev-tools/verify-min-parity.js     （改了样式或脚本就跑一次）
  ↓
上传 dist/document-theme.js → 前台 Ctrl+F5
```

写文档配图时跑 `node _dev-tools/shot-docs.js`，会重新截 `docs/images/` 里那三张。
