# 文章页增强与主题色

v7.20 加的四样东西，都在**页脚脚本**里自动跑，不需要配置、不需要往后台多贴任何字段：

| 功能 | 出现在哪 | 数据从哪来 |
|:---|:---|:---|
| 阅读时长 | 文章页标题与正文之间 | 正文文本（去掉代码工具条与版权块） |
| 标题锚点 | 每个 `h2` / `h3` 右侧，悬停显现 `#` | 标题自身的 `id` |
| 版权块 | 正文最末尾 | 文章作者、`#post-date`、当前 URL |
| 主题色面板 | 顶栏，暗色按钮左侧 | 6 套内置色，读者选择存 `localStorage` |

---

## 一、阅读时长

算法只有一条：**按「字」算，不按字符算**。

- 中文、标点、全角符号：一个字符算一个字
- 英文与代码：每 6 个非空白字符折成一个字（否则一篇纯代码文章会被算成几千字）
- 阅读速度取 350 字/分钟，不足 1 分钟按 1 分钟显示

```js
units = cjk + Math.round(other / 6);
min   = Math.max(1, Math.round(units / 350));
```

**必须先算字数再插版权块**。顺序反了，版权声明那几十个字会被算进正文，长文里看不出来，短文里能差出一分钟。

字数的取法是把正文节点 `cloneNode` 一份再取 `textContent`，并且先摘掉三类节点：

- `script` / `style`：博客园可能插的统计片段
- `.qb-code-bar`：代码块的「JAVA 复制」工具条
- `.qb-copyright`：版权块自己

克隆是为了不在真实节点上做删除 —— 哪怕下一帧就补回来，用户也可能看到正文闪一下。

## 二、标题锚点

```html
<h2 id="添加元素-扩容">添加元素-扩容<a class="qb-hanchor" href="#添加元素-扩容"></a></h2>
```

三个约束：

1. **锚点里不能有文本**。左栏目录取的是 `h.textContent`，锚点写了 `#`，目录每条后面都会多一个井号。所以 `#` 由 CSS 画：

   ```css
   #cnblogs_post_body .qb-hanchor::before { content: '#'; }
   ```

2. **标题没 `id` 时自己补**，格式 `qb-sec-N`。目录生成器只补 `qb-h-N`，两边不冲突；谁先跑都行，后跑的看到已有 `id` 就直接复用。

3. **不做「点击复制链接」**。复制要权限、要提示、要处理失败，收益只是省一次右键；锚点本身就是个 `<a href="#id">`，右键即可复制，所以这里只负责跳转。

悬停显现靠 `opacity`，不是 `display`：`display` 切换会让标题行高跳一下。

触屏没有 hover，`@media (hover: none)` 下锚点常驻 `opacity: .38`，否则手机上永远点不到。

> 博客园自己会给每个标题塞一个 `.cnblogs-toc-button`（那个「≡」按钮）。桌面端左栏已有目录，它只是把标题变成「标题 ≡ #」，所以只在 ≥861px 隐藏；小屏左栏是收起的，那个按钮反而有用，保留。

## 三、版权块

结构（全部用 `createElement` 拼，不用 `innerHTML`）：

```
版权声明
本文作者：Ep流苏　首发：2021-07-23
原文链接：https://www.cnblogs.com/zhangshuaiyin/p/15049767.html
文章均为个人实践总结，转载请注明作者与原文链接。
```

取值规则：

| 字段 | 来源 | 取不到时 |
|:---|:---|:---|
| 作者 | `.postDesc a[href^="http"]` 的第一个链接文本（长度 < 24 才认） | 博客名（从 `title` 推导），再退「博主」 |
| 首发日期 | `#post-date` 文本，只取 `YYYY-MM-DD` | 该行不显示日期 |
| 原文链接 | `location.origin + location.pathname` | 一定有 |

为什么用 `location` 而不是 `<link rel=canonical>`：博客园详情页**没有** canonical 标签。去掉 `query` 与 `hash` 后，得到的正是文章永久地址。

版权原文直接沿用博客公告里那句「文章均为个人实践总结，转载请注明出处」，没有替作者声明任何 CC 协议 —— 许可证是法律声明，不能主题替他做主。

## 四、主题色面板

顶栏右侧、暗色按钮左边的一颗「颜料滴」。点开是 6 个色点，选完立即生效并记住。

| 键 | 值 |
|:---|:---|
| `localStorage` 键名 | `qb-theme` |
| 取值 | `purple`（默认）/ `blue` / `teal` / `orange` / `green` / `rose` |
| 注入的 `<style>` id | `qb-theme-sel` |

### 为什么不是配置项

配色是**读者当下想看什么**，不是站长的固定设置。做成 `LS_CONFIG.theme` 的话，读者每次来都得重新点，而且站长改一次品牌色会把读者的选择冲掉。所以它和暗色放同一层：`localStorage` > `LS_CONFIG.accent` > 样式表默认。

### 优先级细节

- 选「紫（默认）」**不注入任何样式**，而是把选择权交回给 `LS_CONFIG.accent`。站长设了蓝色，读者点「默认」应该看到蓝色，而不是被主题硬钉成紫色。
- 每套色给两个值：浅色底用饱和的那支，暗色底用提亮的那支。同一个 `#3b82f6` 放到 `#0d1117` 上对比度不够，会发闷。
- `--accent-deep` 由主色派生：浅色乘 0.82 压暗，暗色向白色混 20% 提亮。`--accent-soft` 用 `rgba()` 同色低透明度。
- 注入的选择器必须三个并列：

  ```css
  :root, html.qb-dark, body.qb-dark { … }
  ```

  暗色下 `html` 与 `body` 各自重定义了 `--accent`，只写 `:root` 会被那两条盖回去。这条坑 v7.17 之前踩过一次。

### 首帧

`applyTheme()` 与 `syncDarkClass()` 并列执行，都在页面第一次绘制之前。晚一步的后果是：读者刷新时先看到一帧紫色，再跳成自己选的蓝色。

## 五、不想要怎么办

四样都是「没有开关」的默认行为，因为都只是附加信息、不改动正文排版结构。确实想去掉，往「页面定制 CSS 代码」末尾加：

```css
#post_detail .qb-readtime { display: none !important; }
#cnblogs_post_body .qb-hanchor { display: none !important; }
#cnblogs_post_body .qb-copyright { display: none !important; }
.qb-theme { display: none !important; }
```

只藏图标不藏功能是没用的：脚本照样会建节点，CSS 只是不画出来。真要减 DOM，就得改脚本。
