## 一、怎么确认真生效

打开任意页面 → `Ctrl+U` 看源码，搜四个关键词：

| 搜什么 | 期望 | 说明 |
|:---|:---|:---|
| `--qb-field` | **1 处**（第 1 行） | CSS 字段贴对了 |
| `@view-transition` | **1 处** | 跨页过渡生效 |
| `document-theme.js` | **1 处**（在 `document.write` 里） | 加载器正确 |
| `qb-right` | **0 处** | 有的话说明页脚旧脚本没清干净 |

页面元素：`#qb-left` 存在（左栏）、`#sideBarMain` 是右栏容器、`#qb-right` **不存在**。

打开控制台看元素面板更快：`#qb-left` 有内容、`#sideBarMain` 里挂着公告与搜索/积分/排行榜、顶栏 59px。

## 二、排错

| 现象 | 原因 | 处理 |
|:---|:---|:---|
| 切页还是先看到博客园原生皮肤再变 | CSS 字段没贴或贴的是旧内容 | 搜源码有没有 `--qb-field` |
| 顶栏在切页时塌成一条线 | CSS 里缺 `min-height` | 重新贴 `样式.css`（v7.17 起有） |
| 顶栏离顶部 8px 再跳回去 | CSS 里缺 `html,body{margin:0}` | 同上 |
| 切页时顶栏变淡 | 视图过渡规则是旧版 | 确认有 `::view-transition-old(qb-nav)` 那段 |
| 没有过渡效果，就是硬切 | 浏览器不支持跨文档视图过渡 | Firefox 等暂不支持，行为等同无过渡，可忽略 |
| 右栏有卡片但左栏没目录 | js 到了但 `#qb-left` 没建 | 控制台看报错 |
| 右栏内容先在左边闪一下 | 页脚旧脚本没清 | 页脚字段全选删除 |
| 两套顶栏 / 两份目录 | 页脚或公告字段还有旧内容 | 两个都清空 |
| 归档页退回单月列表 | 「随笔档案」小部件被关掉了 | 后台侧边栏设置里重新勾上 |

## 三、切页不闪：实测与修法

**先说结论：跨页面跳转本身必然重建页面，这一点改不了；但「顶部导航会动」是真 bug，已经修掉。**

浏览器点链接换页 = 丢掉整个文档、重新下载解析。新旧两页之间那一段（下载 → 解析 → 第一次绘制）浏览器只能先清屏。主题用跨文档视图过渡把这段盖住，实测空白帧归零。

### 3.1 抓到并修掉的三个原因

| 实测到的问题 | 证据 | 修法 |
|:---|:---|:---|
| 顶栏从 8px 处跳到 0 | 切页后第 2 帧 `nav.top=8`，第 3 帧才 `0` | 首帧样式里写 `html,body{margin:0!important}` —— 那 8px 是浏览器给 `<body>` 的**默认边距**，样式没到位前它一直存在 |
| 顶栏高度 0 → 59 | `nav.h=0` 有一帧，之后才 `59` | `.qb-nav{min-height:58px}` —— 页首里顶栏是个外层 div，撑高度的 `.qb-nav-inner` 还没解析到时，外层是 0 高，整条塌成一根线 |
| 整页先按博客园原生皮肤画一遍，js 到了再整页换 | 首帧 `#top_nav` 露出来、三栏变单列 | **CSS 字段改贴完整样式**（不再是几百字节的闸门），首帧就是最终外观；js 检测到字段里有样式就跳过注入，不再换第二次 |

修完之后逐帧采样：`nav.top` 只出现两个值（`-1` = 还没解析、`0` = 已就位），**再也没有 8**；`nav.h` 全程恒为 `59`；切页过程 **0 帧空白**（改前 3 帧）。

### 3.2 切页过程实测（1360×900，真实博客园页面）

点击文章页里的「首页」链接，用 CDP screencast 逐帧录屏，判断依据是每帧 jpeg 的字节数（1360×900 纯色帧压完只有 7~12 KB，有内容的一般 40 KB 以上）。

| 时刻 | 相对点击 | 画面 | 顶栏 | 字节数 |
|:---|:---|:---|:---|---:|
| 34ms | 点击瞬间 | 旧页（文章页） | 正常 | 97 KB |
| 287ms | 旧页仍在 | 旧页 | 正常 | 97 KB |
| 329ms | 过渡开始 | 旧页 → 新页淡入 | **清晰，不变淡** | 90 KB |
| 430ms | 过渡中 | 新页内容逐渐显现 | **清晰，不变淡** | 42 KB |
| 493ms | 过渡中 | 新页基本可见 | 清晰 | 77 KB |
| 653ms | 过渡结束 | 新页（首页） | 清晰 | 111 KB |
| 743ms | 稳定 | 新页 | 清晰 | 117 KB |

**空白帧 0**。改前同一动作：`296ms / 404ms / 413ms` 三帧 7 KB（纯色），即 200ms 左右的白闪。

关键在「顶栏」那一列：过渡期间页面主体在淡入淡出，**顶栏始终清晰**。实现方式是跨文档视图过渡给顶栏单独命名（`view-transition-name: qb-nav`），两张快照都强制不透明 —— 浏览器默认会把命名元素也一起做交叉淡入，实测顶栏 logo 和菜单会整个变淡，那就是「导航闪了一下」的来源。

> 兼容性：Chromium 126+ / Safari 18+ 支持跨文档视图过渡。
> 不支持的浏览器（Firefox）直接忽略这几条规则，退回普通导航，**不会更差**。

### 3.3 结构层改了什么

| | 旧实现 | v7.16 起 |
|:---|:---|:---|
| 左栏 | 借用 `#leftcontentcontainer` | 脚本新建 `#qb-left` |
| 右栏 | 脚本新建 `#qb-right`，把卡片搬进去 | **直接用 `#sideBarMain`**，公告与卡片本就在里面 |
| 卡片搬运 | 每次填充都要搬一次 | **完全取消**，一个节点都不动 |
| 首帧样式 | CSS 在 js 里，脚本到了才注入 | **CSS 字段给完整样式**，首帧即终态 |

`#qb-left` / `#mainContent` / `#sideBarMain` 三者各占 grid 的一列（260 / 1fr / 292）。右栏内容晚到只改变右栏自身高度，**推不动正文和左栏** —— 这是「不抖」的结构性原因，不再靠时序去赌。

## 四、装完以后怎么改

| 想改什么 | 怎么做 |
|:---|:---|
| 颜色、间距、暗色、字体 | 只上传 `document-theme.js` |
| 目录 / 公告 / 归档时间线逻辑 | 只上传 `document-theme.js` |
| 顶栏菜单 | 改页首里的 `LS_CONFIG.nav`，或只传 js（见[自定义顶栏](自定义顶栏.md)） |
| 增删侧栏小部件 | 博客园后台「侧边栏设置」，不用碰主题 |

> **为什么改样式也不用重贴那 33 KB**：js 里带着同一份 CSS，只是检测到字段里已经有（`--qb-field:1`）就跳过注入。所以字段是「首帧兜底」，js 是「最新实现」，js 里那份永远优先。

## 五、三种分发形态

仓库里只留默认的托管版（`dist/paste/` 两份）。另外两种形态不囤产物，需要时现生成：

| 形态 | 生成命令 | 什么时候用 |
|:---|:---|:---|
| `hosted`（默认） | `python _dev-tools/gen-deploy.py` | 只传文件，不粘贴（[README](../README.md) 讲的就是这个） |
| `hybrid` | `python _dev-tools/gen-deploy.py --mode hybrid` | 想让顶栏在 js 到达前就有菜单 |
| `inline` | `python _dev-tools/gen-deploy.py --mode inline` | 完全不想让页面有外部请求（代价：每次改版重贴 37 KB 页脚） |

`hybrid` / `inline` 按四份（页首 / 页脚 / 公告 / 样式）输出到对应子目录，装法见[备选-内联安装](备选-内联安装.md)。
